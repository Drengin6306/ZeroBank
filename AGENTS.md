# ZeroBank Agent Development Guide

Quick reference for AI coding agents working on the ZeroBank microservices project.

## Build & Test Commands

```bash
# Build all services
make build

# Build specific service
cd service/account/api && go build
cd service/account/rpc && go build

# Build Docker images
make docker

# Run single test
go test -run TestFunctionName ./path/to/package

# Run all tests
go test ./...

# Run with coverage
go test -cover ./...

# Format & lint
go fmt ./...
goimports -w .
go mod tidy

# Generate from proto/api files
cd service/account/rpc
goctl rpc protoc account.proto --go_out=. --go-grpc_out=. --zrpc_out=.
```

## Code Style

### Import Order
Standard lib → Third-party → Local packages (blank lines between groups)

```go
import (
    "context"
    "database/sql"

    "github.com/zeromicro/go-zero/core/logx"
    "github.com/zeromicro/go-zero/core/stores/sqlx"

    "github.com/Drengin6306/ZeroBank/pkg/errorx"
    "github.com/Drengin6306/ZeroBank/service/account/rpc/proto"
)
```

### Naming Conventions
- **Packages**: lowercase single word (`auth`, `errorx`)
- **Files**: lowercase with underscore (`account_model.go`)
- **Types**: PascalCase (`AccountModel`, `TransferLogic`)
- **Functions**: PascalCase (exported) or camelCase (private)
- **Constants**: PascalCase or UPPER_SNAKE (`ErrNotFound`, `MAX_RETRY`)
- **Variables**: camelCase (`accountID`, `userInfo`)

### Error Handling
Always use the unified error code system in `pkg/errorx`:

```go
// Return standard error
if account.Balance < amount {
    return errorx.NewError(errorx.ErrBalanceNotEnough)
}

// Error with custom message
return errorx.NewErrorWithMsg(errorx.ErrRiskControl, "风控拒绝: " + reason)

// Log and wrap errors
if err != nil {
    l.Logger.Errorf("operation failed: %v", err)
    return nil, fmt.Errorf("operation failed: %w", err)
}
```

## Database Transactions

**CRITICAL**: Always use pessimistic locking for balance operations:

```go
func (l *DeductBalanceLogic) DeductBalance(in *proto.Request) (*proto.Response, error) {
    var resp *proto.Response
    
    // Use transaction with pessimistic lock
    err := l.svcCtx.AccountModel.Trans(l.ctx, func(ctx context.Context, session sqlx.Session) error {
        // SELECT ... FOR UPDATE
        account, err := l.svcCtx.AccountModel.FindOneForUpdate(ctx, session, in.AccountId)
        if err != nil {
            return err
        }
        
        // Update balance
        account.Balance -= in.Amount
        err = l.svcCtx.AccountModel.WithSession(session).Update(ctx, account)
        if err != nil {
            return err
        }
        
        resp = &proto.Response{AccountId: account.AccountId, Balance: account.Balance}
        return nil
    })
    
    return resp, err
}
```

## DTM Distributed Transactions

Use DTM SAGA pattern for distributed transactions. **Must provide compensation logic**:

```go
// Current setup: DTM connects via Docker service names
accountRpcTarget := "account-rpc:9001"

saga := dtmgrpc.NewSagaGrpc(l.svcCtx.Config.DTM.Server, transactionID)

// Add forward + compensate actions
saga.Add(
    accountRpcTarget+"/account.Account/DeductBalance",
    accountRpcTarget+"/account.Account/CompensateDeduct",  // Rollback action
    &account.DeductBalanceRequest{AccountId: from, Amount: amount},
)

saga.WaitResult = true
err := saga.Submit()
```

## go-zero Framework Rules

### Generated Code
- **DO NOT EDIT**: Files marked `// Code generated by goctl. DO NOT EDIT.`
- **SAFE TO EDIT**: Files marked `// Code scaffolded by goctl. Safe to edit.`
- Custom logic goes in `customXXXModel` or `XXXLogic` files

### Logic Layer Pattern
```go
type TransferLogic struct {
    logx.Logger
    ctx    context.Context
    svcCtx *svc.ServiceContext
}

func NewTransferLogic(ctx context.Context, svcCtx *svc.ServiceContext) *TransferLogic {
    return &TransferLogic{
        Logger: logx.WithContext(ctx),
        ctx:    ctx,
        svcCtx: svcCtx,
    }
}

func (l *TransferLogic) Transfer(req *types.TransferRequest) (*types.TransferResponse, error) {
    // 1. Validate params
    // 2. Business logic
    // 3. Return response
}
```

## Best Practices

1. **Always pass context** for timeout control
2. **Keep transactions small** - minimize lock duration
3. **Design for idempotency** - especially compensation actions
4. **Check nil pointers** before dereferencing
5. **Use defer** for resource cleanup
6. **Protect shared resources** with pessimistic/optimistic locks

## Common Issues

- **After modifying .proto**: Re-generate code and rebuild
- **LSP errors but builds succeed**: Run `go mod tidy`, restart IDE
- **Config switching**: `make config-local` / `make config-docker`
