# AGENTS.md - ZeroBank 代理开发指南

本文件为 AI 编码代理提供 ZeroBank 项目的开发规范和指南。

## 构建、测试和 Lint 命令

### 构建命令

```bash
# 构建所有服务
make build

# 构建单个服务（在服务目录下）
cd service/account/api && go build
cd service/account/rpc && go build

# 构建 Docker 镜像
make docker

# 快速启动（停止 -> 构建 -> 运行）
make quickstart
```

### 测试命令

```bash
# 运行所有测试
go test ./...

# 运行特定服务的测试
go test ./service/account/...

# 运行单个测试文件
go test ./pkg/auth/jwt_test.go

# 运行单个测试函数（使用 -run 标志）
go test -run TestFunctionName ./path/to/package

# 运行测试并显示覆盖率
go test -cover ./...

# 生成覆盖率报告
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

### Lint 和代码质量

```bash
# 格式化代码
go fmt ./...
gofmt -s -w .

# 使用 goimports（自动管理 imports）
goimports -w .

# 检查代码（需要安装 golangci-lint）
golangci-lint run

# 整理依赖
go mod tidy

# 验证依赖
go mod verify
```

### Proto/API 代码生成

```bash
# 从 .api 文件生成 HTTP API 代码
cd service/account/api
goctl api go -api account.api -dir .

# 从 .proto 文件生成 gRPC 代码
cd service/account/rpc
goctl rpc protoc account.proto --go_out=. --go-grpc_out=. --zrpc_out=.

# 或使用原生 protoc
protoc --go_out=. --go-grpc_out=. account.proto
```

## 代码风格指南

### 包导入规范

导入顺序：标准库 → 第三方库 → 本地包，每组之间用空行分隔。

```go
import (
	"context"
	"database/sql"
	"fmt"

	"github.com/zeromicro/go-zero/core/logx"
	"github.com/zeromicro/go-zero/core/stores/sqlx"
	"google.golang.org/grpc"

	"github.com/Drengin6306/ZeroBank/pkg/errorx"
	"github.com/Drengin6306/ZeroBank/pkg/vars"
	"github.com/Drengin6306/ZeroBank/service/account/rpc/proto"
)
```

### 命名约定

- **包名**：小写单词，简短有意义（如 `auth`、`errorx`、`model`）
- **文件名**：小写下划线分隔（如 `account_model.go`、`jwt_test.go`）
- **类型名**：大驼峰（如 `AccountModel`、`TransferLogic`）
- **函数/方法名**：大驼峰（导出）或小驼峰（私有）
- **常量**：大驼峰或全大写下划线（如 `ErrNotFound`、`MAX_RETRY_COUNT`）
- **变量名**：小驼峰，简洁有意义（如 `accountID`、`userInfo`）

### 类型和结构体

```go
// 使用有意义的类型别名
type ResCode uint32

// 结构体字段按重要性排序，带注释
type Account struct {
	AccountId   string  // 账户ID（主键）
	Balance     float64 // 余额
	Status      int     // 状态：0-正常 1-冻结
	AccountType int     // 类型：0-个人 1-企业
	CreatedAt   time.Time
	UpdatedAt   time.Time
}

// 接口定义清晰，方法按功能分组
type AccountModel interface {
	accountModel
	// 事务相关
	WithSession(session sqlx.Session) AccountModel
	Trans(ctx context.Context, fn func(context.Context, sqlx.Session) error) error
	// 查询相关
	FindOneForUpdate(ctx context.Context, session sqlx.Session, accountId string) (*Account, error)
}
```

### 错误处理

**使用统一错误码系统**（`pkg/errorx`）：

```go
// 定义错误码（code.go）
const (
	Success ResCode = 200
	ErrInvalidParams  ResCode = 1000 + iota
	ErrNotLogin
	ErrAccountNotFound  ResCode = 2000 + iota
	ErrBalanceNotEnough
)

// 使用错误码
if account.Balance < amount {
	return errorx.NewError(errorx.ErrBalanceNotEnough)
}

// 带自定义消息的错误
return errorx.NewErrorWithMsg(errorx.ErrRiskControl, "风控拒绝：" + reason)

// 检查并处理错误
if err != nil {
	return nil, err // 简单传递
}

if err != nil {
	l.Logger.Errorf("操作失败: %v", err) // 记录日志
	return nil, fmt.Errorf("操作失败: %w", err) // 包装错误
}
```

### 事务和数据库操作

**使用悲观锁保证并发安全**：

```go
func (l *DeductBalanceLogic) DeductBalance(in *proto.DeductBalanceRequest) (*proto.DeductBalanceResponse, error) {
	var resp *proto.DeductBalanceResponse

	// 使用事务和悲观锁
	err := l.svcCtx.AccountModel.Trans(l.ctx, func(ctx context.Context, session sqlx.Session) error {
		// SELECT ... FOR UPDATE 悲观锁
		account, err := l.svcCtx.AccountModel.FindOneForUpdate(ctx, session, in.AccountId)
		if err != nil {
			return err
		}

		// 业务逻辑检查
		if account.Balance < in.Amount {
			return errorx.NewError(errorx.ErrBalanceNotEnough)
		}

		// 更新数据
		account.Balance -= in.Amount
		err = l.svcCtx.AccountModel.WithSession(session).Update(ctx, account)
		if err != nil {
			return err
		}

		resp = &proto.DeductBalanceResponse{
			AccountId: account.AccountId,
			Balance:   account.Balance,
		}
		return nil
	})

	if err != nil {
		return nil, err
	}
	return resp, nil
}
```

## 项目特定规范

### 分布式事务（DTM）

使用 DTM SAGA 模式处理分布式事务，必须提供补偿逻辑：

```go
// 创建 SAGA 事务
saga := dtmgrpc.NewSagaGrpc(l.svcCtx.Config.DTM.Server, transactionID)

// 添加正向操作和补偿操作
saga.Add(
	target+"/Service/Method",     // 正向操作
	target+"/Service/Compensate", // 补偿操作
	&Request{...},
)

// 提交事务
saga.WaitResult = true
err = saga.Submit()
```

## 最佳实践

1. **始终使用 context**：传递上下文用于超时控制和取消传播
2. **事务边界清晰**：数据库事务尽可能小，避免长事务
3. **幂等性设计**：所有操作（尤其是补偿操作）必须幂等
4. **防御性编程**：检查 nil 指针、数组边界、除零等
5. **资源清理**：使用 defer 确保资源释放
6. **并发安全**：使用悲观锁或乐观锁保护共享资源

## 常见问题

1. **修改 proto 后**：必须重新生成代码并重新编译
2. **LSP 错误但编译成功**：通常是缓存问题，运行 `go mod tidy` 并重启 IDE
3. **测试数据库**：使用 Docker 启动测试数据库或使用内存数据库
4. **配置切换**：使用 `make config-local` 和 `make config-docker` 切换配置
